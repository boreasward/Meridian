# Meridian v1 · P0 实施计划：搭底座仓库

对应设计：[2026-11-14-meridian-v1-design.md](../specs/2026-11-14-meridian-v1-design.md) 第 4–12 节、第 13 节的 P0。

目标：Meridian 仓库里有全部同步文件、扩展文件模板、同步脚本、锁文件测试、画廊和合并后的设计规范；对一个空目录同步后 `--check` 无差异。本计划不改 Windrose 和 Bearing。

## Global Constraints

- 只在 `main` 上开发，不 `git push`。
- 不改令牌取值、字体、圆角、阴影。
- 两边逐字相同的文件用复制，不重写；首版来源见设计第 6 节。
- 同步文件里不出现项目名（Windrose、Bearing）和项目的业务词。
- 每个 Task 只跑本 Task 相关的检查；前端全量（`cd web && npm install && npm test && npm run build`）只在 Task 6 跑一次。
- 依赖版本与两个项目现在的 `package.json` 完全一致。

## 执行顺序与依赖

Task 1 → Task 2 → Task 3 → Task 4 → Task 5 → Task 6，顺序执行。Task 4（分发）与 Task 5（画廊、规范）的文件互不重叠，可以并行；清单 `meridian.manifest.json` 归 Task 4。

## Task 1：仓库骨架与两边相同的代码

- `README.md`、`CLAUDE.md`、`VERSION`（`0.1.0`）、`CHANGELOG.md`、`.gitignore`。
- `web/`：`package.json`（`meridian-web`）、`vite.config.ts`、`vitest.config.ts`、`vitest-setup.ts`、`tsconfig.json`、`svelte.config.js`、`components.json`、`index.html`（标题 Meridian，图标是圆加竖线）。
- 从 Windrose 复制：`styles/tokens.css`、`styles/app.css`、`styles/tokens.test.ts`、`lib/utils.ts`、`lib/theme.ts` 及测试、`lib/ui/` 的通用组件、`lib/ui/domain/` 的 `DataBlock`、`PageHeader`、`Section`、`ExternalLink` 及测试。
- 从 Bearing 复制：`lib/ui/{popover,select,sheet,tabs,tooltip}/`。
- `styles/app.css` 顶部加 `@import './project.css'`；Meridian 自己的 `project.css` 为空。

检查：复制来的文件与来源逐字相同（`app.css` 除外）。

## Task 2：扩展点

- `lib/ui/domain/tone.ts`：`Tone`。
- `lib/ui/domain/status.ts`：底座域 `block`（`not_computed`、`insufficient`）加 `$lib/app/status` 的词表合成一张表；`statusOf`；`labelText`（项目没导出就原样返回）。项目词表不得重新定义 `block`。
- `lib/ui/domain/StatusPill.svelte`：文字经 `labelText`。
- `lib/ui/domain/icons.ts`：底座图标加 `$lib/app/icons` 的表。
- `lib/ui/copy.ts`：`UNREACHABLE`、`UNAVAILABLE`。
- `lib/ui/format.ts`：`fmtTime`（可选时区与后缀）、`fmtClock`、`fmtDuration`、`isHttpUrl`；`ExternalLink` 改从这里引 `isHttpUrl`。
- `lib/stores/resource.svelte.ts`：Windrose 版加 `reset()` 与 `emptyWhen`；取数与错误文案只经 `$lib/api` 的 `get`、`errorText`。测试用 `vi.mock('$lib/api')`，不依赖任何项目的接口客户端。
- `lib/views/ResourceBlock.svelte` 及测试。
- Meridian 自己的 `lib/app/status.ts`、`lib/app/icons.ts`、`lib/api.ts`（画廊用的假接口）。
- `templates/`：五个项目扩展文件的模板。

检查：`svelte-check` 通过；`StatusDomain`、`IconName` 能从合成后的表推出（设计第 15 节第 2 项风险）。

## Task 3：应用壳与页面骨架

- `lib/shell/layout.svelte.ts`：左栏折叠、抽屉面板、窄屏；键名 `ws.nav.collapsed`、`ws.drawer`。
- `lib/shell/NavList.svelte`、`NavRail.svelte`、`TopBar.svelte`、`Drawer.svelte`、`AppShell.svelte`：props 见设计第 8 节；`AppShell` 导出 `dismissOverlay()`；`<main>` 由壳提供。
- `lib/ui/domain/Page.svelte`、`PageCard.svelte`（`title` 可选）。
- 各自的测试。

检查：`svelte-check` 通过。

## Task 4：分发

- `meridian.manifest.json`：同步文件（glob）、模板、共用依赖版本。
- `scripts/sync.py`：同步、`--check`、`--allow-dirty`；行为见设计 5.2。
- `web/meridian.lock.test.js`：有锁文件时逐个比对 sha256，且不得 `dirty`；在 Meridian 自己（有清单、没有锁文件）里只检查清单存在。
- `tests/meridian_guards.py`：通用守护（设计第 12 节），含两条新检查；`tests/test_frontend_design_guards.py`：Meridian 自己的入口。
- `tests/test_sync.py`：同步到空目录、再次同步幂等、改动同步文件后 `--check` 失败、过期文件被删除、已有的扩展文件不被覆盖、依赖版本不一致时失败。

检查：`pytest tests -q`。

## Task 5：画廊与设计规范

- `web/src/app.svelte`、`main.ts`、`routes/*.svelte`：画廊本身用 `AppShell`（带抽屉），页面分为令牌、组件、状态与数据块、页面骨架四页。
- `docs/design-system.md`：两份规范合并，加上壳、页面骨架、品牌、文案与格式四节。

检查：`svelte-check` 通过；守护测试通过。

## Task 6：收尾验收

- 前端全量：`cd web && npm install && npm test && npm run build`。
- `pytest tests -q`。
- 对一个空的临时目录运行 `scripts/sync.py`，再运行 `--check`，无差异。
- 验证设计第 15 节第 1 项风险：在 `project.css` 里临时加一个 `@theme inline` 映射，构建后的 CSS 里有对应的工具类；验证完撤回。
- 全量 code review 一次。
